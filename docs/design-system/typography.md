# Typography

## Purpose

Typography makes operational information scannable, trustworthy, and calm. It should establish hierarchy before containers, color, or decoration are introduced.

## Principles

- Legibility and scan speed come before personality.
- A small type scale creates predictable hierarchy.
- Weight, spacing, and placement should do more work than color.
- Interface copy is concise, direct, and professional.
- Numerical data should remain easy to compare.

## Usage Guidelines

DealerFlow v1 uses a neutral system sans stack and a system monospace stack for technical identifiers.

| Role | Size / line height | Weight | Use |
| --- | --- | --- | --- |
| Display | 30–36 / 36–44 px | 600 | Rare onboarding and major empty states |
| Workspace title | 24–30 / 30–36 px | 600 | Primary context heading |
| Section title | 18–20 / 24–28 px | 600 | Major information groups |
| Component title | 14–16 / 20–24 px | 600 | Cards, panels, dialogs, and table groups |
| Body | 14 / 20 px | 400 | Default content and values |
| Label | 12–14 / 16–20 px | 500–600 | Controls, headers, and compact actions |
| Metadata | 12 / 16 px | 400–500 | Timestamps and supporting context |
| Micro | 11 / 14 px | 600 | Short navigation group labels only |

Use sentence case. Use tabular numerals for financial and comparable operational data. Keep prose left-aligned. Reserve monospace for identifiers where character recognition or alignment matters.

## Do

- Use one clear heading level per hierarchy level.
- Keep labels persistent and concise.
- Allow text to wrap when truncation would hide meaning.
- Test text zoom, localization expansion, and narrow widths.
- Use muted text only for supporting—not essential—information.

## Don't

- Do not use all caps for sentences or actions.
- Do not use more than three weights in one composition.
- Do not shrink text to make a dense layout fit.
- Do not center long-form product copy or operational data.
- Do not use typography as decoration through excessive tracking or weight.
