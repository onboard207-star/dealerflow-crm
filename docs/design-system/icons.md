# Icons

## Purpose

Icons improve recognition, reduce repeated text, and support compact actions. They should feel precise and operational without becoming automotive decoration.

## Principles

- Use one coherent icon family.
- Meaning and familiarity determine whether an icon can stand alone.
- Icons support labels; they do not replace essential language.
- Size and stroke remain consistent with surrounding content.
- Automotive references remain literal and functional.

## Usage Guidelines

Use Lucide as the standard icon language. Use 16 px icons in compact controls, 18–20 px in standard controls, and 24 px only for prominent navigation or empty-state moments.

Leading icons support action meaning. Trailing icons indicate direction, disclosure, or external movement. Decorative icons are hidden from assistive technology. Icon-only controls require an accessible name and usually a tooltip.

Use vehicle, key, wrench, calendar, document, communication, and finance symbols only when they describe actual objects or actions. Keep icon color aligned with text unless a semantic status requires otherwise.

## Do

- Select the simplest recognizable icon for the concept.
- Keep optical size and alignment consistent within action groups.
- Pair unfamiliar or consequential icons with visible text.
- Mirror directional icons in right-to-left contexts when appropriate.
- Verify icon meaning with target dealership users.

## Don't

- Do not mix icon libraries or illustration styles.
- Do not use racing flags, speed lines, chrome, or vehicle silhouettes as decoration.
- Do not communicate status with an icon alone.
- Do not use different icons for the same action across workspaces.
- Do not shrink icons until their form becomes ambiguous.

## Future Considerations

- A reviewed icon registry and usage examples.
- Automotive-domain additions that match Lucide's visual language.
- Duotone or filled states only if a clear interaction need emerges.
- Native-platform icon mapping.
